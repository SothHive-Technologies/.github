# Contributing

Most SothHive repositories are delivery surfaces, not community products. If a repo is open and you want to help, this is how.

## Before you write code

1. Open an issue describing the problem, the expected behaviour, and how you tested it.
2. Wait for a maintainer to confirm the issue is in scope.
3. Keep pull requests small and named after the change, not the ticket number alone.

## Pull requests

- Match the existing code style. PHP goes through Pint; frontend follows the files already in the tree.
- Include a test or a short verification note when behaviour changes.
- Do not commit `.env`, credentials, or client data.
- One concern per PR.

## Security

Do not file public issues for vulnerabilities. Email [info@softhive.com](mailto:info@softhive.com) with enough detail to reproduce, and give us time to patch before disclosure.
